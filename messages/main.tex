Messages are the standardized ways of communication between peers or servers. 
Implementation MUST be identical. To ensure interoperability between encrypted
and unencrypted states, all data transmitted over the channel MUST be 
represented as a sequence of bytes.

\section{Data Representation}

The protocol MUST NOT transmit raw strings directly over the transport layer.
All message content MUST be serialized into JSON format
[\href{https://datatracker.ietf.org/doc/html/rfc8259}{RFC8259}].
\nocite{rfc8259}

\subsection{Character Encoding}

When strings are represented within the JSON payload or converted to bytes, the
UTF-8 encoding scheme MUST be used. Implementations MUST follow strict UTF-8
decoding rules; any malformed sequences MUST result in a silent message
rejection to prevent security vulnerabilities.

\subsection{Serialization and Deserialization}

\begin{itemize}
    \item Serialization: All entities MUST serialize messages into a byte
        stream prior to transmission.
    \item Deserialization: Upon receipt, the byte stream MUST be deserialized
        according to the specific event schemas defined below.
\end{itemize}

\section{Events}

The encryption of an \texttt{Event} object is conditional upon the state of the
session. An \texttt{Event} MAY be transmitted in plaintext only if the
cryptographic session has not yet been initialized. Once the session is
established, all subsequent \texttt{Event} transmissions MUST be encrypted.
\bigskip

Implementations MUST reject any \texttt{Message} or \texttt{Typing} events
received in plaintext after a session has been successfully initialized.
\bigskip

When an \texttt{Event} is encrypted, all associated metadata MUST be included
within the encrypted ciphertext. This includes, but is not limited to,
timestamps, sender identifiers, and message sequences. Encapsulating metadata
ensures that no traffic analysis can be performed on the message properties by
intermediaries.
\bigskip

\texttt{Event} object MUST includes random padding \([\![0;8192]\!]\) bytes. An
encrypted event CANNOT be smaller than 1 kilobyte.
